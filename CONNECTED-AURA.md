# Connected Aura direction

## System Settings

System Settings is the connection layer for networked hardware and software extensions, their data, and memory/storage. It is not just a device inventory or a backup screen. A reconstruction tool, camera or scanner must be able to provide data to Aura; memory/storage must hold the captured data and results that other tools use.

The current browser implementation has project tables, local media storage, and manual device/service records. It does not pair devices, install extensions, discover network resources, pool memory or execute reconstruction jobs. Keep connection state distinct from a saved description. Do not infer that a configured service is connected.

A future extension contract needs to identify the tool, its available input/output formats, the selected data references and storage destination, how jobs are started and observed, and the permission to access those resources. These are implementation requirements to work through with Luke, not a new generic questionnaire to impose on every algorithm.

## Mind Palaces

Source scans, photos and video should support a realistic reconstruction of the captured place. Layout and meaningful landmarks matter. Unobserved areas and AI-created geometry must remain distinguishable from captured geometry. A saved prompt is not reconstruction.

The local capture flow accepts photos, video and scan/model files, stores them locally, separates original media from results, and links the place to Aura tables and instructions. The reconstruction extension, navigable 3D output and anchors on real spatial features remain outstanding.

## Nearby Opportunities and Algorithms

Restore the original concept and navigation. Withdraw the invented generic rule forms. Preserve all existing saved data. Nearby Opportunities needs Luke's actual intended behaviour before another implementation is added.
